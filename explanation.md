# Project Explanation — Career PathFinder

## 1. What This Project Does

**Career PathFinder** is an AI-powered web application that helps people discover career paths that match their existing skills and interests. You enter the skills you already have (e.g. "Python", "SQL", "Communication") and optionally select areas of interest (e.g. "Data Science", "Cybersecurity"). The app then:

1. **Matches you to careers** — it uses a vector-similarity search over 1,000+ real-world job profiles (sourced from O*NET, a US Department of Labor database) to find the roles most aligned with your skill set.
2. **Generates a personalised 6-month learning roadmap** — either via Google's Gemini AI or via a built-in template fallback — so you know exactly what courses to take, projects to build, and milestones to hit.

## 5. How the Project Works

### Complete Application Flow

```text
User visits the website
  │
  ▼
Landing Page ("/")
  │  User clicks "Find my path"
  ▼
Onboarding Page ("/onboard")
  │  User types skills (e.g. "Python, SQL")
  │  User selects interests (e.g. "Data Science")
  │  User clicks "Get Recommendations"
  │
  ├──► POST /api/onboard  →  Backend creates a user profile
  │    { skills, interests }     → Returns { user_id }
  │
  ├──► POST /api/recommend →  Backend:
  │    { user_id }                1. Encodes skills+interests into a vector
  │                               2. Queries ChromaDB for similar career profiles
  │                               3. Returns top 5 career matches with scores
  ▼
Recommendations Page ("/recommendations")
  │  Shows career cards with % match
  │  User clicks "View Path" on a career
  │
  ├──► POST /api/path →  Backend:
  │    { user_id, career }    1. Retrieves user's skills/interests
  │                           2. Sends prompt to Gemini AI (or uses mock)
  │                           3. Returns a 6-month learning roadmap
  ▼
Path View Page ("/path")
  │  Displays the learning roadmap as formatted Markdown
  ▼
Done!
```

### How the vector matching works

1. **Offline (pre-computed):** The `embedding.py` script encodes every career profile (role name + description + required skills) into a 384-dimension vector using the `all-MiniLM-L6-v2` model. These vectors are stored in ChromaDB.

2. **Online (at request time):** When a user submits their skills, the backend encodes those skills into the same vector space and asks ChromaDB: "What career profiles are closest to this vector?" ChromaDB returns the most similar careers ranked by cosine distance.

## 7. Backend Explanation

### Framework
**FastAPI** (Python) — a modern async web framework that auto-generates OpenAPI docs.

### Entry Point
`backend/main.py` — the entire backend is in this single file.

### Important Routes

| Method | Path | Purpose | Input | Output |
|---|---|---|---|---|
| `GET` | `/health` | Health check | — | `{"status": "ok"}` |
| `POST` | `/onboard` | Register a user profile | `{skills, interests}` | `{user_id}` |
| `POST` | `/recommend` | Get career matches | `{user_id}` or `{skills}` | `{careers: [...]}` |
| `POST` | `/path` | Get a learning roadmap | `{user_id, career}` | `{career, learning_path, source}` |

### Key Functions

| Function | What it does |
|---|---|
| `average_embedding()` | Converts a list of skill strings into a single averaged vector |
| `query_career_matches()` | Queries ChromaDB for the top N career profiles similar to the user's vector |
| `generate_learning_path()` | Calls Gemini API with a detailed prompt; falls back to `mock_learning_path()` |
| `mock_learning_path()` | Returns a pre-written 6-month plan for known careers, or a template for unknown ones |

### Database Interaction
- On startup (via the `lifespan` context manager), the backend loads `SentenceTransformer` and opens the ChromaDB persistent database from `chroma_db/`.
- User profiles are stored **in-memory** (a plain Python dict). They are lost when the server restarts.

### Authentication
- **None.** There is no login system. Users are identified by a UUID generated during onboarding.

### External APIs
- **Google Gemini** (`google-genai` SDK) — called only when generating a learning path. If the API key is missing or the call fails, it falls back to a built-in mock template.

### Environment Variables

| Variable | Required? | Purpose |
|---|---|---|
| `GEMINI_API_KEY` | Yes (for AI paths) | Google Gemini API key |
| `GEMINI_MODEL` | No | Override the default model (`gemini-3.6-flash`) |
| `CORS_ORIGINS` | No | Restrict CORS to specific origins (default: `*`) |

### Starting the backend

```bash
cd backend
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

## 8. Database / Storage

### Vector Database: ChromaDB
- **What:** An embedded vector database stored as a SQLite file (`chroma_db/chroma.sqlite3`, ~14 MB).
- **Collection:** `career_profiles` — contains two types of documents:
  - **career** entries (role + description + required_skills) — ~1,000 records
  - **skill** entries (individual skill names) — ~5,000 records
- **How it connects:** The backend opens it on startup using `chromadb.PersistentClient(path="chroma_db/")`.
- **No external database server needed.** It is just a file on disk.

### User Storage
- Users are stored **in-memory** in a Python dict. This means all user sessions are lost on server restart. This is acceptable for a demo/prototype.

### Data Files (CSV)
Located in `data/`:
- `occupation_data.csv` — Raw O*NET occupation titles and descriptions
- `essential_skills.csv` — O*NET essential skills with importance scores
- `transferable_skills.csv` — O*NET transferable skills
- `software_skills.csv` — O*NET software/technology skills
- `careers.csv` — **Processed** (generated by `prepare_data.py`): role, description, required_skills
- `skills.csv` — **Processed** (generated): master list of all unique skills
- `courses.csv` — **Processed** (generated): synthetic course catalog

## 9. AI / ML Components

### Sentence Embeddings (ML)
- **Model:** `all-MiniLM-L6-v2` from the `sentence-transformers` library
- **Purpose:** Converts text (skills, career descriptions) into 384-dimensional vectors
- **How it works:** Both career profiles and user skills are encoded into the same vector space. Similarity is computed via cosine distance.
- **Loaded at:** Backend startup (in the `lifespan` function)
- **No training required** — the model is pre-trained and downloaded automatically from Hugging Face on first run

### Google Gemini AI (LLM)
- **Model:** `gemini-3.6-flash` (configurable via `GEMINI_MODEL` env var)
- **Purpose:** Generates personalised 6-month learning roadmaps
- **Input:** A prompt containing the target career, user's current skills, and interests
- **Output:** A Markdown-formatted learning plan with monthly breakdowns
- **Fallback:** If the API key is missing or the Gemini call fails, a built-in template is used instead
- **Required API Key:** `GEMINI_API_KEY` from Google AI Studio (https://aistudio.google.com/apikey)

## 15. Common Errors

### CORS Error
**Symptom:** Browser console shows "Access to XMLHttpRequest blocked by CORS policy"
**Cause:** Frontend and backend are on different domains but CORS is not configured.
**Fix:** The backend now has CORS middleware. Set `CORS_ORIGINS` to your frontend URL.

### "Failed to submit profile. Is the backend running?"
**Symptom:** Clicking "Get Recommendations" shows this error.
**Cause:** The backend server is not running or the frontend cannot reach it.
**Fix:** Make sure `uvicorn` is running. In production, make sure `VITE_API_URL` points to the correct backend URL.

### Port Already in Use
**Symptom:** `uvicorn` refuses to start with "Address already in use"
**Fix:** Either kill the existing process or use a different port:
```bash
uvicorn main:app --host 0.0.0.0 --port 8001
```

### Slow First Request on Render
**Symptom:** First API call takes 30-60 seconds.
**Cause:** Render's free tier spins down after inactivity. The ML model needs to reload.
**Fix:** This is normal on free tier. Consider upgrading to a paid plan, or use a "keep alive" ping service.

### SentenceTransformer Download Fails
**Symptom:** Backend fails to start with a Hugging Face download error.
**Cause:** No internet access, or Hugging Face is down.
**Fix:** Ensure the deployment platform has internet access during startup. The model is cached after the first download.

### Missing GEMINI_API_KEY
**Symptom:** Learning paths show "Generated via template (demo mode)" instead of AI-generated content.
**Cause:** `GEMINI_API_KEY` is not set or invalid.
**Fix:** Set a valid API key from Google AI Studio. The app still works without it (uses fallback templates).

### Frontend Shows Blank Page in Production
**Symptom:** Deploying the frontend shows a white screen.
**Cause:** `VITE_API_URL` is not set, so API calls go to `/api` which does not exist on the static hosting server.
**Fix:** Set `VITE_API_URL` to your full backend URL before building.

### Build Error: "Cannot find module"
**Symptom:** `npm run build` or `npm install` fails.
**Fix:** Delete `node_modules` and `package-lock.json`, then run `npm install` again:
```bash
cd frontend
Remove-Item -Recurse -Force node_modules, package-lock.json
npm install
```
